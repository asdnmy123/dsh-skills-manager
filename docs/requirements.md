# 技能管理插件需求

## 用户明确要求

- 在 dsh 中添加技能管理页面。
- 管理加载的技能，支持选择技能并执行删除、启用和关闭。
- 交互参考用户提供的 Codex 技能管理页面。
- 每次改动都有对应 Git commit，并更新相关测试，全部验证通过后交付。

## 从截图提炼的界面方向

展示名称、描述、当前状态；提供搜索、刷新与来源分组。
这些是后续界面设计方向，截图中的添加入口和插件安装功能不属于本次初始化范围。

## 后续接入方向

1. 宿主端从 dsh 技能服务读取目录并提供管理操作，浏览器端负责页面与交互。
2. 使用官方客户端页面扩展机制，新增 `./client` 导出和 `dsh.client` 声明。
3. 客户端构建需满足 lazy-CJS factory 格式；普通 TypeScript ESM 构建只用于当前宿主入口。
4. 技能服务存在 scope、来源优先级和提供方概念，列表应明确当前查看的范围及来源。

## 实现前需要核对

- 固定目标 dsh 版本，核对该版本客户端页面注册与通信接口。
- 启用/关闭是否已有管理接口、状态写在哪里，以及如何影响后续模型和用户调用。
- 删除操作对本地、随包、远程与虚拟技能的适用范围。
- 禁用后的技能仍应在管理列表中可见，以便重新启用。
- 变更如何触发目录失效和页面刷新，以及是否影响运行中的会话。

## 后续验收方向

- 列表来自宿主真实技能目录，展示加载、空列表和错误状态。
- 关闭后技能不可按既定策略调用，重新启用后恢复；状态按约定在重启后保留。
- 删除前确认目标，操作只影响所选且允许管理的技能；删除失败有明确反馈。
- 覆盖不同来源、同名技能、重复操作、重启恢复及插件卸载场景。

当前初始化测试只覆盖骨架、宿主生命周期和分发配置，不表示上述业务功能已经完成。
